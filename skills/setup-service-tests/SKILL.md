# Setup Service Tests

Generate a complete service test infrastructure for a given microservice repository. This creates everything needed to run integration tests: k8s manifests, mock configurations, test utilities, Tiltfile, docker-compose, and one working test.

## Input

`$ARGUMENTS` is the path to the service repository to test (e.g., `/Users/sganot/code/ti-my-service` or just `ti-my-service`).

## Phase 1: Analyze the Service

Use an Explore agent to analyze the target service repository. Find:

1. **Language & Framework**: Check `package.json` (Node.js: Express, NestJS) or `pyproject.toml`/`requirements.txt` (Python: FastAPI, Flask)
2. **API Endpoints**: Search for route decorators/handlers:
   - NestJS: `@Get`, `@Post`, `@Patch`, `@Delete`, `@Controller`
   - FastAPI: `@app.get`, `@router.post`, etc.
   - Express: `router.get`, `app.post`, etc.
3. **External Service Dependencies**: Look for:
   - HTTP clients (axios, httpx, requests) calling other services
   - Environment variables with `_URL`, `_HOST`, `_SERVICE` patterns
   - Connector/client modules that wrap external API calls
4. **Database**: Check for:
   - TypeORM entities, SQLAlchemy models, Mongoose schemas, PyMongo usage
   - Connection strings in env vars (`DATABASE_URL`, `MONGO_URI`, `POSTGRES_*`)
5. **Message Queues**: Look for:
   - Google Pub/Sub (`@google-cloud/pubsub`, `google.cloud.pubsub_v1`)
   - Topic/subscription names in env vars
6. **Entity/Model Schemas**: Read the actual field definitions to replicate in tests

## Phase 2: Clarify

Ask the user:
- **For JS/TS services only**: "Should tests be written in Python or TypeScript?" (Python is default for Python services)
- **If many endpoints found**: "Which endpoints/flows are most critical to test first?"
- **If dependencies are unclear**: Confirm which external services need mocking

## Phase 3: Run Templater to Generate Base Scaffold

The templater tool generates a basic service test infrastructure. Follow these steps:

```bash
# Move to ti-service-test root
cd /Users/sganot/code/ti-service-test

# Install dependencies (if not already installed)
poetry -C template install

# Activate virtualenv created by Poetry
$(poetry -C template env activate)

# Run the templater to generate base scaffold
python -m templater generate --service-name <service-name> --lang python --provider gcp
```

**Service name format**: Use kebab-case (e.g., `ti-my-service`). The template creates a directory with underscores: `ti_my_service/`.

**Add dependencies during generation** (optional):
```bash
# Add dependencies with --add parameter
python -m templater generate --service-name <service-name> --lang python --provider gcp --add pubsub --add gcs
```

**Or add dependencies after generation**:
```bash
# Add individual dependencies later
python -m templater add --service-name <service-name> pubsub
python -m templater add --service-name <service-name> firestore
python -m templater add --service-name <service-name> gcs
```

**Supported dependencies**:
- `pubsub` - Google Pub/Sub emulator + fixtures
- `firestore` - Firestore emulator + fixtures
- `gcs` - GCS emulator (fake-gcs-server) + fixtures

**What the templater generates**:
- `pyproject.toml` - Python dependencies
- `Dockerfile` - Test container image
- `Tiltfile` + `Tiltfile-common` - Local k3d testing
- `kubernetes/base/` - Core k8s manifests (service deployment, test pod, kustomization)
- `kubernetes/overlays/` - Debug/profiler variants (optional)
- `tests/test_dummy.py` - Placeholder test

This creates the foundation. The next phase adds infrastructure on top of this scaffold.

## Phase 4: Generate Additional Infrastructure

Build on top of the templater-generated scaffold. The base structure now exists in `/Users/sganot/code/ti-service-test/<service_slug>/`. 

**What's already generated by templater**:
- ✅ `pyproject.toml` with basic test dependencies
- ✅ `Dockerfile` for test container
- ✅ `Tiltfile` and `Tiltfile-common` for local testing
- ✅ `kubernetes/base/<service-name>.yaml` - service deployment
- ✅ `kubernetes/base/service-test-pod.yaml` - test runner pod
- ✅ `kubernetes/base/kustomization.yaml` - base resources
- ✅ `kubernetes/base/settings.env` - environment variables
- ✅ `kubernetes/kustomization.yaml` - main kustomization
- ✅ `tests/test_dummy.py` - placeholder test
- ✅ If `--add pubsub`: Pub/Sub emulator + fixtures
- ✅ If `--add gcs`: GCS emulator + fixtures
- ✅ If `--add firestore`: Firestore emulator + fixtures

**What you need to add**:
- External service mocks (MockServer deployments for HTTP dependencies)
- MongoDB/PostgreSQL (if not using templater dependencies)
- Mock data files (`kubernetes/mock_data/*.json`)
- Realistic test files (replace `test_dummy.py`)
- Update `pyproject.toml` with service-specific dependencies

**Directory structure after templater**:
```
ti_service_name/
├── Dockerfile
├── Tiltfile
├── Tiltfile-common
├── pyproject.toml
├── kubernetes/
│   ├── kustomization.yaml          # Main kustomization
│   ├── base/
│   │   ├── kustomization.yaml      # Base resources
│   │   ├── <service-name>.yaml     # Service deployment
│   │   ├── service-test-pod.yaml   # Test pod
│   │   └── settings.env            # Environment vars
│   ├── overlays/                   # Optional debug/profiler overlays
│   └── [templater-added-deps].yaml # If --add used
└── tests/
    └── test_dummy.py
```

### 4.1 Kubernetes Manifests (`kubernetes/`)

The templater already created `kubernetes/base/kustomization.yaml` with the service and test pod. Now update `kubernetes/kustomization.yaml` to include additional resources:

**kubernetes/kustomization.yaml** - Update to add external dependencies:
```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  # Base resources (already created by templater)
  # If templater added pubsub/gcs/firestore, they're already listed here
  - <dependency-name>-mock.yaml   # Add one per external HTTP service
  - mongo.yaml                    # If MongoDB (not generated by templater)
  - postgres.yaml                 # If PostgreSQL (not generated by templater)
  
# If templater created base/ directory with kustomization, reference it:
bases:
  - base/

configMapGenerator:
  # Templater may have already created service-settings configMap
  # Add configMap per mock that uses initialization JSON:
  - name: <dependency>-config
    files:
      - ./mock_data/<dependency>.json
```

**Note**: Check what templater already generated. If you used `--add pubsub`, it already created `pubsub-emulator.yaml` and `gcs-emulator.yaml`. Don't duplicate them.

**Mock Server Deployments** - One per external HTTP dependency. Use this template:
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: <dependency-name>-mock
  annotations:
    kapp.k14s.io/change-group: "apps.r7ops.com/ci-test-services"
spec:
  replicas: 1
  selector:
    matchLabels:
      app: <dependency-name>-mock
  template:
    metadata:
      labels:
        app: <dependency-name>-mock
    spec:
      containers:
        - name: <dependency-name>-mock
          image: mirror.gcr.io/mockserver/mockserver:5.14.0
          ports:
            - containerPort: 5000
          env:
            - name: MOCKSERVER_INITIALIZATION_JSON_PATH
              value: /config/<dependency-name>.json
            - name: MOCKSERVER_SERVER_PORT
              value: "5000"
          volumeMounts:
            - name: config-volume
              mountPath: /config
      volumes:
        - name: config-volume
          configMap:
            name: <dependency-name>-config
---
apiVersion: v1
kind: Service
metadata:
  name: <dependency-name>-mock
  annotations:
    kapp.k14s.io/change-group: "apps.r7ops.com/ci-test-services"
    cloud.google.com/load-balancer-type: Internal
spec:
  selector:
    app: <dependency-name>-mock
  ports:
    - protocol: TCP
      port: 5000
      targetPort: 5000
  type: LoadBalancer
```

### 4.2 Mock Data (`kubernetes/mock_data/`)

For each external HTTP service mock, create a JSON file with MockServer initialization expectations. Analyze the service's connector code to understand what requests it makes and generate realistic responses:

```json
[
  {
    "httpRequest": {
      "method": "GET",
      "path": "/api/resource/[0-9a-fA-F]{24}"
    },
    "httpResponse": {
      "statusCode": 200,
      "body": {
        "id": "5a7869e7811c5f00065847ca",
        "status": "active",
        "name": "Test Resource"
      }
    }
  }
]
```

Use regex patterns in paths where IDs are dynamic. Generate responses that match the actual API contracts the service expects.

## Phase 5: Generate Test Code

### For Python tests (default):

**pyproject.toml** - Update dependencies beyond the base template:
```toml
[project]
dependencies = [
    "pytest (>=9.0.2,<10.0.0)",
    "httpx (>=0.27.0,<1.0.0)",
    "pymongo (>=4.8.0,<5.0.0)",         # if MongoDB
    "google-cloud-pubsub (>=2.23.0,<3.0.0)",  # if Pub/Sub
    "faker (>=30.0.0,<31.0.0)",
]
```

**tests/conftest.py** - Shared fixtures:
```python
import os
import pytest
import httpx

API_URL = os.environ.get("API_URL", "http://localhost:8080")
# Add per dependency:
# MOCK_URL = os.environ.get("<DEPENDENCY>_MOCK_URL", "http://localhost:5000")
# MONGO_URI = os.environ.get("MONGO_URI", "mongodb://localhost:27017/")
# PUBSUB_EMULATOR_HOST set as env var

@pytest.fixture
def client():
    return httpx.Client(base_url=f"{API_URL}/api/<service-prefix>/v1", timeout=5.0)

@pytest.fixture
def mock_client():
    return httpx.Client(base_url="http://<dependency>-mock:5000", timeout=5.0)

# Database fixture (MongoDB example)
@pytest.fixture
def database():
    import pymongo
    mongo = pymongo.MongoClient(host=os.environ.get("MONGO_URI"))
    db = mongo["<database_name>"]
    yield db
    # Cleanup collections after each test

@pytest.fixture(autouse=True)
def cleanup(database):
    yield
    for collection_name in database.list_collection_names():
        database[collection_name].delete_many({})
```

**tests/test_<flow_name>.py** - One working test:
```python
def test_<basic_flow>(client, database, mock_client):
    # 1. Setup: prepare test data
    # 2. Mock: set expectations on mock servers (if dynamic mocks needed beyond static JSON)
    # 3. Execute: call the service endpoint
    response = client.get("/endpoint")
    # 4. Assert: verify the response
    assert response.status_code == 200
    assert response.json()["field"] == expected_value
```
